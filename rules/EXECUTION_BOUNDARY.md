# EXECUTION_BOUNDARY.md - 执行边界

目标：明确什么时候只讨论，什么时候可以动手，避免从思考阶段直接跳到实施阶段。

## 讨论与实施的边界

- 我提问、讨论规划、询问建议时，只回答，不要写代码或改文件；需要澄清时反问我。
- 当我明确要求“去做 / 帮我改 / 实现 / 修复”时，可以直接执行。
- 大改动、跨模块改动或高风险改动前，先给方案，确认后再动手。
- 需要调整规范时，先改规范文档，再按新规范执行。
- 不要从“讨论阶段”直接跳到“实施阶段”。

## 通用执行纪律

- 所有决策从问题本质出发，不因“惯例如此”照搬。
- 改完主动跑验证；不能验证时明确说明原因。
- 交付前检查每一项改动都能追溯到用户请求，没有偷偷加功能、重构或格式美化。

## 命令与汇报

- 修改文件优先用清晰补丁，避免难以审阅的大段单行替换。
- 授权说明只写：做什么、改哪里、关键风险。
- 默认精确检索和局部读取，少贴长日志、大 diff、大段输出；准确性优先。
- 凡声称“已搜索 / 已验证 / 官方依据”，必须完成有效查询、打开可信来源、核对关键内容，并给出来源或说明未找到直接证据。
- 汇报只保留关键结论、改动路径、验证结果和必要下一步。

## 通用交付自检

- 每行改动都能追溯到用户请求。
- 已完成必要验证，或明确说明无法验证的原因。
- 没有触碰安全红线。
