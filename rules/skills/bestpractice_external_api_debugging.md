# 外部 API / 协议 / SDK 调试

## 元数据

- **类型**: BestPractice
- **适用场景**: 调试外部 API、第三方协议、SDK、官方接口接入问题
- **创建日期**: 2026-07-08
- **来源**: 从全局 CLAUDE.md 拆分，沉淀为任务型调试规范

## 目标

优先用参考实现和逐字段比对缩短排障路径，避免靠猜测驱动用户做高成本验证。

## 核心约束

- 第一时间找官方文档或可运行参考实现，包括 GitHub demo、SDK 源码。
- 逐字段对比 headers、body、参数生成逻辑和工具函数内部实现。
- “看起来差不多”不算对比过。
- 所有明确差异一次性修完再测试，避免让用户反复配合高成本操作。
- 禁止无证据归因；“可能是 X”必须先验证再下结论。
- 调试超过两轮未解决，停止同方向试错，改为找参考实现、搜索已知问题或对比工作版本 diff。

## 推荐流程

1. 先拿到官方文档和一个可运行参考实现。
2. 列出当前实现与参考实现的关键字段差异。
3. 一次性修正已确认差异。
4. 再做最少次数的验证。
5. 两轮未解时换策略，不继续堆日志和猜测。

## 典型反模式

- 先猜 token、base URL、环境变量、缓存问题，再让用户重复操作。
- 每次只改一个字段就要求用户重新验证。
- 没核对 SDK 源码内部行为，就凭接口文档下结论。
