# 并行 Subagent 工作流

## 目标与适用范围

在独立检索、代码探索或交叉审查能减少耗时和遗漏时使用子代理。最终交付由主线程整合、验证并负责。单点小任务、强顺序依赖和多人修改同一文件时，优先串行。

当前客户端为 Codex CLI、Kimi CLI、Zcode。使用当前会话实际提供的子代理工具和参数；不假设不同客户端共享调用协议，不把 Coding Plan 订阅等同于可跨客户端调用的 API。

## 执行边界

- 先检查当前运行时是否允许委派，以及可用工具、并发上限、等待和取消方式。
- 无子代理能力时，主线程按同样的任务划分串行完成，并如实说明验证是否独立。
- 只使用已暴露的模型或 agent；默认继承当前会话配置，不固定模型品牌或旧 agent 别名。
- 敏感材料遵循已授权的数据边界；云端订阅不代表本地执行或零留存承诺。
- 多个 agent 可以并行读取；修改时明确各自拥有的文件，避免同时覆盖。

## 拆分与交接

一般拆成 2–3 个可独立验收的任务。调研可在关键证据上保留重叠，代码实现按模块分界。并发数量服从当前运行时限制，超出上限时分批。

每个任务交代清楚：

- 目标、负责范围、排除范围和验收标准。
- 应读取的文件或来源、输出文件路径。
- 与其他任务的交界和需要复核的证据。
- 输出语言默认与用户一致。

材料较多时通过 `tmp/<session_slug>/<task_name>/` 下的文件交接。Prompt 传目标与路径；子代理返回产物路径、完成状态、关键结论和未解决项。结果极短时可直接返回，避免为小任务增加无意义文件。

主线程从原始证据和产物整合，处理矛盾并完成最终验证，不直接拼接各 agent 的总结。

## 等待与恢复

采用当前工具说明规定的等待、状态查询和取消机制，不套用其他客户端的工具名。长期任务保留中间产物，巡检参考 [后台任务巡检](./workflow_watchdog.md)。任务中断后先读取已有成果，再决定恢复或重做。

## 验收

- 每个子任务有明确状态；未完成项没有混入已完成结论。
- 最终结果能追溯到来源或修改文件，关键分歧已核对。
- 所有必要的代码或文档检查由主线程确认通过。
- 未超出用户授权范围，没有借委派绕过权限或发布限制。
