# 个人文风改写工作流

## 元数据

- **类型**: Workflow
- **适用场景**: 需要把中文草稿改写成用户自己的写作风格，用于公众号文章、博客、评论型长文、AI/技术解读和方法论写作
- **输出位置**: 就地返回改写稿；如用户指定文件路径，则写回指定文件
- **创建日期**: 2026-05-29
- **最近更新**: 2026-09-05 — 增补从本人真实文章（离职感悟文）提取的风格特征：设问驱动、自嘲补刀、金句收尾、TM 级情绪表达、黑色幽默等

## 目标

把用户提供的中文草稿改写成更像用户本人写出来的版本。

这个 skill 的重点不是“润色得更顺”，而是同时做到三件事：

1. 保留原文的核心立场和关键要点
2. 把表达改成用户自己的口吻、节奏和判断方式
3. 对删掉的要点和原文本身的逻辑问题保持显式交代，不偷偷处理

## 边界

这个 skill 做：

- 按用户个人文风改写中文草稿
- 统一口吻、节奏、段落长度和解释方式
- 显式标注被删除的要点
- 显式指出原文已有的逻辑问题

这个 skill 不做：

- 不改变用户的核心立场
- 不把有判断的文本改成安全、中性、无观点的摘要
- 不偷偷删除关键论点后假装只是“优化表达”
- 不把改写变成泛泛的“AI 味”润色

## 用户画像与风格锚点

默认读者画像：

- 25-40 岁互联网职场人
- 关注效率、工具、个人成长、AI 工作流
- 对技术不陌生，但不接受教材腔和咨询腔

默认文风约束：

- 口语化，用“你”“我”，像跟朋友聊天
- 多用短句，段落尽量不超过 4 行
- 有观点，不模棱两可，敢下结论
- 喜欢用生活类比解释复杂概念

绝对不用的表达：

- 赋能
- 闭环
- 颗粒度
- 在这个快节奏的时代

### 风格特征清单（从本人真实文章提取）

以下特征提取自本人亲写的文章（职场感悟/评论类，2026-09 提供）。改写感悟类、评论类文章时，这些特征比上面的通用约束优先级更高。

**结构与节奏**

- 设问驱动：小节标题直接用问句（"职场人的第一要务？"、"我是不是完蛋了？"），自问自答推进全文
- 三连排比铺垫，然后一个转折判断："见识过不少X……见识过不少Y……见识过不少Z……但是，[核心判断]"
- 短段落，一两句一段；每节收在一个可摘抄的金句上
- 判断句放段尾，砍掉判断前面的铺垫修饰

**口吻与人设**

- 第一人称对读者说"你"，像跟朋友喝酒聊天，不是写专栏
- 敢自嘲、敢自我暴露：主动承认自己没做到（"我就是这样的知行不合一"），常用括号补刀自嘲（"（说我自己呢）"、"（可能我容易内耗）"）
- 强情绪处允许"TM"级别的粗口替代字（"身体太TM重要了"），增强真实感，但不真的骂人；不要把这类表达洗成书面语
- 坦率谈利益和诉求，不装清高：直接说自己在沉迷什么、想认识什么人、想要什么

**论证方式**

- 个人具体经历 → 普适判断：先给细节（跑了很多楼盘最终没出手、父亲确诊、二宝出生），再抽道理；细节必须具体到数字和实物，不许抽象化
- 引用他人观点（带引号），然后自己重新解读，解读往往和常识相反
- 列举具体到条目级：说身体预警就列"皮肤：暗沉、痒、湿疹"，说赛道就列"AI套壳、出海、SEO"
- 借流行文化词汇给抽象概念命名："打分思维"、"思想钢印"——造词让读者记得住
- 数字具体化：10%/90%、20%、35岁、六年

**金句质感**

- 判断句短、狠、可摘抄："大厂的终局就是离开"、"打工不错，但最好还是别打了"
- 正话反说、黑色幽默："你比不喜欢的人活得长久，是不是一种成功呢？"、"怪不得企业招工要35以下呢"
- 脆弱与感谢并置：列完感谢清单，马上暴露脆弱（"我曾经一度认为，除了打工我一无是处"）
- 情绪诚实但不卖惨：承认焦虑内耗之后，必有"向前看吧"式的转折，列举正在变好的事

**口语连接词**（本人高频使用，可自然穿插）

- "瞧吧"、"是的"、"换句话说"、"更可悲的是"、"猛地发现"、"先声明"、"事实上"

风格锚点示例：

示例一（科普解释类，用生活类比讲概念）：

> 很多人甚至没搞明白大模型和 AI 工具的概念。Claude Code 和 Opus，Sonnet，Haiku 都是属于 Anthropic 公司的产品，Claude Code 是 AI 编程工具，Opus，Sonnet，Haiku 属于 A 社的大模型。  
> 你可以理解为模型是大脑，Claude Code 是一个有手有脚帮你干活的强壮身体，目前 Opus 模型是 A 社的最强大脑。  
> 拿 A 社的最强模型 Opus 举例。  
> 如果你想使用 Claude Code + Opus 整个产品，就相当于用上了一个最强大脑 + 最强壮身体，这个组合是 A 社的官方完整产品，也是目前公认全球最强组合。  
> 身体 Claude Code 不收费，任何人都可以用，而且不用注册账号，只是模型收费，需要注册账号。

示例二（个人感悟/评论类，本人亲笔原句）：

> 是的，在没有其他buff加持的情况下，老板就是最大的资源。
> 更可悲的是，一个人一旦被证明了擅长做脏活累活，那么脏活累活继续是他的。
> 我懂了这么多，你问我做没做到？我没有。我就是这样的知行不合一。
> 身体太TM重要了，一辈子长着呢，你比不喜欢的人活得长久，是不是一种成功呢？
> 猛地发现，从离开校园的那一刻起，"卷子"没了。人生从一场有限博弈，变成了无限博弈。
> 最怕的是内耗，既要又要，两头都不沾。（说我自己呢）
> 打工不错，但最好还是别打了。

## 方法论建议

先判断“这篇草稿的核心立场是什么”，再判断“哪些句子只是表达问题，哪些是逻辑问题”。

改写时优先处理以下几类问题：

- 摘要腔太重，句子像在汇报而不是在说话
- 观点太弱，判断藏在泛泛叙述里
- 段落太长，节奏拖慢
- 解释抽象，没有生活类比或具体场景
- 重复说同一个点，但没有增加信息量

优先保留这些东西：

- 用户下结论的位置
- 用户自己的类比、命名和 framing
- 能体现作者观察密度的句子

改写感悟类、评论类文章时，额外遵守：

- 保留"设问标题 + 自问自答"的骨架，不要改成陈述式小标题
- 判断句挪到段尾，金句保持短句形态，不加修饰词
- 自嘲补刀优先放括号里，位置跟随它嘲讽的那句话
- 具体细节（数字、身体部位、项目名）不许抽象化，一抽象就失真
- 强情绪处如果原稿有"TM"级表达，保留力度；如果原稿平淡但内容情绪浓，可以补一处，全文不超过两处
- 每一节检查一遍：结尾是不是落在一个可摘抄的判断句上

## 验收标准

满足以下条件，才算这个 skill 被正确执行：

1. 改写后的正文读起来像用户本人，而不是像通用 AI 编辑器
2. 核心立场、主要判断和关键要点没有被改写成别的意思
3. 绝对不用的表达零出现
4. 段落长度基本符合“尽量不超过 4 行”的约束，除非逻辑需要
5. 如果删除了原文要点，结果里必须显式写出：`删除了：xxx`
6. 如果原文逻辑有问题，结果里必须显式写出：`逻辑问题：xxx`
7. 如果没有删除重要要点或没有明显逻辑问题，也必须显式写出：`删除了：无`、`逻辑问题：无`

## 输出规格

默认输出顺序固定：

1. 改写后的正文
2. `删除了：...`
3. `逻辑问题：...`

如果用户要求写回文件：

- 只写入改写后的正文，还是连同诊断说明一起写入，必须按用户请求执行
- 如果用户没有说明，默认正文与诊断说明一起返回，不擅自覆盖文件中的其他结构

## 已知陷阱

当前版本先记录一个高频真实风险：

- 最容易发生的错误，不是“改得不够顺”，而是把有判断的草稿改成平滑但没劲的安全版本。只要改写后读起来像平台摘要，而不像作者本人，这个 skill 就算失败。
