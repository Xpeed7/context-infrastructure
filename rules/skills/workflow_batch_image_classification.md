# 批量图片分类与归档工作流

## 元数据

- **类型**: Workflow
- **适用场景**: 对一批照片/扫描件（几十到几百张，如病历票据、报销单据、证件材料）按用户给定的类别体系识别内容，并整理到分类文件夹
- **输出位置**: 用户指定的分类目录（建议新建 `<原目录名>-分类整理/`，不改动原目录）
- **创建日期**: 2026-07-24

## 目标

给定一个图片目录和一套类别定义，让每张图片被正确识别、归入恰好一个类别，并按类别复制/移动到对应子文件夹，整理前后文件总数对账一致。

## 验收标准

一个没有任何上下文的 agent 可用以下标准判断是否完成：

1. 原目录中每个文件恰好出现在一个分类子文件夹中，无遗漏、无重复。
2. 同一份多页文件（同一文档的第 1/N、2/N 页）整体归入同一类别，不拆分到多个文件夹。
3. 分类子文件夹文件数之和等于原目录文件数，已用命令对账验证。
4. 每类至少抽查过归属正确性，特例规则（用户指定的例外归类）已逐条落实。
5. 用户被告知：归类结果的类别分布、发现的重复照片、与用户预期不一致的地方（如文件内容与目录命名不符）。

## 可用资源与边界

- **并行子代理**：识别阶段用并行子代理分批读图，主 agent 不直接读原始图片。拆分原则参考 `workflow_parallel_subagents.md`（执行类任务 overlap 取 0%）。
- **shell 图像工具**：macOS 自带 `sips`（压缩）、`md5`（查重）；有 Python 环境时可用 `imagehash` 做相似图查重。
- **边界**：默认**复制**而非移动到分类目录，除非用户明确要求移动。不删除任何原文件。

## 方法论建议（建议，非硬约束）

- **每批 8～12 张图**交给一个子代理。单个子代理塞太多图，尾部图片的识别质量会下降。
- **压缩后再识别**：`sips -Z 1600` 把长边缩到 1600px，单图 token 消耗可降一半以上，票据文字仍然清晰。模型看图有分辨率上限，超出部分是纯浪费。
- **先查重**：手机连拍常见同一文件拍两次（内容相同的重复照片），用 md5 或感知哈希先找出，重复的只识别一次。
- **利用文件名先验**：连拍照片的时间戳是强分组信号，同一时间段的连拍往往属于同一类材料。可对每个时间段抽样识别一两张预判该批性质，只细看边界处的图片。
- **子代理输出格式**：要求每个文件一行 `文件名 | 类别 | 标题 | 日期 | 特例标记`，并注明多页连续关系。结构化输出让主 agent 整合时不需要回看图片。

## 已知陷阱（来自真实任务，2026-07 病历票据分类）

**陷阱一：分类规则只传了类别定义，没传冲突裁决原则。** 用户规则「贝伐珠单抗相关材料一律归其他材料」传下去了，但没说明：一份出院记录正文里提到该药算不算「相关材料」？多页文件中只有一页命中特例规则怎么办？结果 3 个子代理各自猜测，同一份出院记录被拆到两个类别，输出里堆满「需要你确认」的犹豫段落，主 agent 被迫逐条二次裁决。**应对**：给子代理的分类规则必须包含两层——(1) 类别定义，(2) 裁决原则：特例规则与文档本质冲突时谁优先、多页文件按整体归类还是按页归类。默认原则是「按文档本质归类，特例规则只针对以该事物为主题的专项材料；多页文件不拆分」。

**陷阱二：原图直接喂模型。** 2～7MB 的手机原图直接识别，token 消耗比压缩后高一倍以上，识别质量没有差别。**应对**：识别前统一压缩到长边 1600px 左右的临时目录，识别用压缩图，归档仍用原图。

## 执行参考流程

1. 列出目录文件，md5 查重，标注重复组。
2. 生成压缩图临时目录（识别用）。
3. 与用户确认类别体系和特例规则，补齐裁决原则（见陷阱一）。
4. 分批并行识别，收集结构化结果。
5. 主 agent 整合裁决，输出完整「文件 → 类别」映射。
6. 创建分类目录，复制文件，对账总数（验收标准 1、3）。
7. 汇报：各类别数量、重复照片、异常发现。

## 不适用场景

- 少量图片（<20 张）：直接串行识别即可，不值得起并行和压缩流程。
- 需要逐字转录图片内容（OCR 全文提取）而非分类：本工作流只保证类别判断可靠。
