# AI 工作流：把 AI 真正融入你的日常 — 文章总结

## 核心观点

AI 工作流不是某个工具或系统，而是**你在做某类事情时固定用到 AI 的步骤和用法**。没有工作流的人每次"想怎么用"，有工作流的人每次"直接用"。

## Skill vs 工作流

- **Skill**：一个动作（如写作风格改写），解决"这一步怎么做得好"
- **工作流**：一整套流程，解决"从头到尾怎么串起来"
- 两者可互相嵌套：Skill 是工作流的零件；跑顺的工作流也能打包成更大的 Skill

## 公众号写作工作流（八步详解）

> 选题 → 大纲 → 初稿 → 风格改写 → 人工打磨 → 排版 → 生成头图 → 推送草稿箱
> 你      AI     AI      Skill       你       AI/你    AI        AI

### 第一步：选题（你为主，5 分钟）
- 给 AI 一个方向，让它发散 5 个选题角度
- 自己选定或追问调整，和 AI 聊不超过 3 轮
- 关键：你定方向，AI 帮发散

### 第二步：大纲（AI 为主，10 分钟）
- **不要直接让 AI 写全文**，先出 6-8 节大纲
- 同一会话中操作，利用上下文提高准确度
- 你做三件事：看顺序对不对、删多余的、补自己想加的

### 第三步：初稿（AI 为主，20 分钟）
- **逐节写**，每节 200-300 字，不要一次全写
- AI 注意力集中时质量更高，偏了立刻纠正
- 你是导演，AI 是编剧——把控方向和质量

### 第四步：风格改写（Skill，5 分钟）
- 用写作风格 Skill 一键改写，去掉 AI 味
- Skill 里固化了口吻、节奏、禁用词、示例风格
- 没有 Skill 也可以在对话里手动指定风格要求

### 第五步：人工打磨（你为主，15-20 分钟）
- **AI 解决 0→70 分的苦力活，70→90 的灵魂必须自己来**
- 加入真实案例和经历
- 调整开头和结尾
- 删掉"正确但没必要"的内容

### 第六步：排版（AI/你，3 分钟）
- 用排版 Skill 或脚本自动转换格式
- 也可截图喜欢的排版风格让 AI 写 md→html 脚本

### 第七步：生成头图（AI，2 分钟）
- AI 按品牌风格生成封面图
- 定好风格后让 AI 生成脚本，后续自动渲染

### 第八步：推送草稿箱（AI/你，2 分钟）
- 通过公众号 API 自动推送排版好的文章和封面
- 需要配置 API Key 和 IP 白名单

**总计约 60 分钟**，产出一篇有结构、有风格、有真实内容的文章（之前需大半天）。

## 减少AI味的关键

不要找主题后让 AI 一股脑写完再改。按照工作流逐步操作：选题和大纲人工干预 → 逐节让 AI 写 → 写完人工干预 → 按自己风格改写 → 再打磨。流程下来质量高、AI 味少。

## 建立工作流的通用三步法

1. **拆步骤** — 这件事通常分几步？
2. **标角色** — 每一步是 AI 做、你做、还是 Skill 做？
3. **固定下来** — 写下来，下次直接执行

## 四个常见坑

1. **想一次做完美** — 先跑起来，用一周再改
2. **什么都想用 AI** — 每周重复 3 次以上的任务才值得做工作流
3. **想一口气全自动化** — 先手动跑通，找最痛的一步优先自动化
4. **做好后不更新** — 每隔一两周回顾优化

## 进阶：把工作流打包成 Skill

手动跑过 5-10 次确认稳定后，可将整套流程写成 Skill 指令文档。做成 Skill 后你的角色从"流程执行者"变成"流程监督者"，只需在关键节点拍板。

典型文件结构：
```
wechat-writing-workflow/
├── workflow.md              ← 主流程指令
├── skills/writing-style.md  ← 写作风格 Skill
├── scripts/
│   ├── format.js            ← 排版脚本
│   ├── cover.js             ← 封面图生成
│   └── publish.js           ← 推送草稿箱
└── templates/
    ├── format-template.html ← 排版模板
    └── cover-template.html  ← 封面图模板
```

## 一句话总结

别每次用 AI 都从零开始，把固定的步骤变成固定的流程：拆步骤 → 标角色 → 固定下来 → 跑一遍 → 迭代。
