## 导语

这篇文章系统讲了多人/多 Agent 协作的四个层面：Git 分支工作流（多人协作）、git worktree（单人多 Agent 并行开发）、`~/.agents/` 全局约束目录（多 Agent 统一规范）、项目内三份文档（AGENTS.md / ROADMAP.md / README.md 解决长期记忆）。

**与本 workspace 的关联**：文中提出的 `~/.agents/AGENTS.md` 作为唯一 source of truth、各 CLI 软链接适配的做法，正是本机全局 AGENTS.md 里「Global Agent Infrastructure」一节的落地实践源头；项目三文档（AGENTS.md / ROADMAP.md / README.md）也对应本 workspace 的治理规范。文中另附一篇旧帖（见附录），详细讲了这套多 Agent 全局约束的演进过程。

## 正文

我在微信内部分享其中一个主题就是：团队多人多 Agent 协作，今天姑且系统的把这个主题也一并给球友们分享下。

如果你现在只是一个人做，那么可能感触不深，但是现在即便你一个人，可能也会用多 Agent 来做，比如 Codex，Kimi Code 等。那么我会分情况来直接提供思路和解决方案。

### 1. 多人协作同一个项目

如果团队多人同时做一个项目，那就会导致一个问题，AI 同时改一个文件，会导致冲突，所以软件开发领域的标准就是 Git。

做过技术的同学对 Git 不陌生，但是如果没做过技术的，建议大家借助 AI 去了解下 Git，这几乎是必学知识点。

简单来说，Git 是一个分布式管理工具，你在公司开发一个项目，把代码推送到 Git 服务器或者 GitHub，那么回到家的时候，直接把项目同步下来，就会随时随地多设备获得项目最新进展代码。而且即便未来某一天，你的电脑坏了，文件丢了，那么你的项目在 Git 服务器也有，也没有任何担心。

那么如果多人同时协作一个项目的话，简单来说就是一句话 **Git Branch**，也就是分支。

比如 A 要做一个功能开发，他的分支是 `feat/a`

B 同时做另一个功能开发就是分支 `feat/b`

其中 feat 是 feature 的缩写。而分支命名也是有一套标准的：

- 主分支 `main/`
- 功能分支 `feat/`
- 修复 bug 分支 `bugfix/`
- 正式发布分支 `release/`

做完测试 ok 再合并到 main 主分支。

这就是一套标准的多人协作的 Git 分支工作流。

细节就不多说了，大家借助自己的 AI 去学习下，这是全球软件开发行业的通用标准，几乎全球顶级科技公司基本都是这套。

### 2. 多 Agent 协作并行开发

如果你一个人，同时用 Codex，Kimi Code 同时开发一个项目，那么有个东西叫做 **git worktree**，你不知道没关系，直接告诉你的 AI，当你遇到这个场景的时候，让 AI 用 worktree 去并行开发，这样你的每个 Agent 相当于有个独立的工作区，彼此互不干扰，做完再合并。

### 3. 多 Agent 的统一全局约束规范

如果你本地有多个 Agent，比如 Codex，Kimi Code，Grok 等，每个全局约束 AGENTS.md 都写一份太重复太傻瓜了，甚至于你 Codex 装的 skills，mcp 等在其他 Agent 也应该生效才对。

虽然现在一些 Agent 自己会做通用适配，但是本质原理还是全局建立一个目录 `~/.agents/AGENTS.md`，`~/.agents/skills` 等，然后让你的 AI 去帮你做软链接适配就好。

之前星球我提到过这个点，帖子链接在这里（全文见附录）。

### 4. 项目内的三份文档

至于项目内的三份文档 **AGENTS.md，ROADMAP.md，README.md** 在我的全局 AGENTS.md 里其实都定义好了，这三份文档解决了项目开发的长期记忆问题，你每次做完功能开发记得来一句「更新文档」就好，这样任何人，任何 Agent 都可以无缝接手，你也可以随时关闭会话窗口。

以上基本就是团队多人多 Agent 协作的标准且最合理的做法，这个帖子如果你暂时不理解，建议你收藏到你的知识库，等你以后遇到的时候，这个帖子一定对你有非常大价值。

## 附录：多 Agent 全局约束配置文档的演进（CLAUDE.md 和 AGENTS.md 问题）

> 这是主帖第 3 节引用的星球旧帖，讲 `~/.agents` 这套做法的来龙去脉。

今天上来给大家更新一个关于多 agent 的全局约束配置文档 CLAUDE.md 和 AGENTS.md 问题。

**1.** 首先在两个月前，我主力一直是 claude code，但是随着最近各家 AI 公司能力逐渐追平，Anthropic 再也不是断崖式领先了，而且我现在不只是编程，我对图片，视频等场景都会涉及到，所以 AI 生态非常重要。

而 Codex 无论模型能力，还是 Agent 能力还是 OpenAI 的生态，现在早都是我的主力开发工具了。

所以我内部所有项目都以 AGENTS.md 为基准。

**2.** 但是随着我本地 Agent 越来越多，比如我本地的 Agent 有 claude code，codex，kimi code，grok 等等，当然都是 cli agent，每家的全局约束标准都不一样，之前的做法，我一份 CLAUDE.md，然后在每个 AGENTS.md 写明，全局约束以 CLAUDE.md 为准。

但是我发现一个问题，各家 Agent 对 AGENTS.md 的预加载机制不一样，很多 Agent 并不会默认加载整个文档内容，只加载一个对应的链接关系。

再加上，随着 Agent 越来越多，其实应该有套标准的。

**3.** 所以我现在的最新做法，虽然还不是整个 AI 界的通用标准，但是我有预感，我这套做法，未来很有可能会是 AI 界的通用标准做法。

我的做法是：

1. 创建 `~/.agents` 全局本地 agents 标准目录。
2. 新增 `~/.agents/AGENTS.md`，这就是全部本地 agent 依赖的全局约束文档，只有一份就好。
3. 为每家 agent 对应的创建软链接，比如各家对应的全局约束文档 `~/.claude/CLAUDE.md`，`~/.codex/AGENTS.md`，`~/.kimi-code/AGENTS.md` 等等
4. 以后变更，只需要变更 `~/.agents/AGENTS.md` 一份文档就好，其他 agent 自动同步。
5. 未来本地增加更多的 cli agent，追加一个软链接就好。
6. 以后通用的 skills，mcp 等都同样安装在 `~/.agents` 目录，让你的 AI 自动去适配就好。
